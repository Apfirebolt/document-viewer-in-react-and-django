# Document Viewer

Document Viewer is a document-management application with a Django REST API and a React client. Users can register, sign in, upload supported files, and manage their own documents. The client also includes profile, user-list, and admin views.

## What is included

- **Backend:** Django 6, Django REST Framework, PostgreSQL, and Simple JWT authentication.
- **Frontend:** React 18, Vite, Redux Toolkit, and Tailwind CSS.
- **API reference:** OpenAPI schema and an interactive Swagger UI generated by `drf-spectacular`.

The document API accepts PDF, TXT, JPG, JPEG, and PNG files up to 5 MB. Documents are stored under `media/documents/`. The database has a model for shared documents, but the current API does not expose document-sharing endpoints.

This also includes smooth token refresh mechanism on the front-end which replaces token smoothly behind the scenes once a token is expired through making a request to the refresh token end-point.

## Repository layout

```text
accounts/             Custom user model and account configuration
api/                  REST API views, serializers, routes, and tests
client/               React application and Vite configuration
documents/            Document data models and upload configuration
document_viewer/      Django project settings and root URL configuration
media/                Local uploaded files
templates/            Django-rendered root page and shared templates
```

## Requirements

- Python 3.12 or newer (Django 6 requirement)
- PostgreSQL
- Node.js and npm

## Run locally

### 1. Configure PostgreSQL and Django

Create a PostgreSQL database named `document_viewer`, or update the `DATABASES` setting in `document_viewer/settings.py` to match your local database. The checked-in settings use the database name `document_viewer`, user `postgres`, password `pass123`, host `localhost`, and port `5432`.

These values, along with the checked-in Django secret key and `DEBUG = True`, are development defaults. Replace them and use environment-based secrets and production-safe settings before deploying; the project does not currently load these settings from a `.env` file.

From the repository root, create and activate a virtual environment, then install the backend dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Apply database migrations and start Django:

```bash
python manage.py migrate
python manage.py runserver
```

The Django server listens at <http://localhost:8000>. Create an administrator account when needed with `python manage.py createsuperuser`.

### 2. Run the React client

In a second terminal:

```bash
cd client
npm install
npm run dev
```

Open the Vite URL shown in the terminal, normally <http://localhost:3000>. The Vite development server proxies `/api` requests to Django at `http://localhost:8000`, so keep both servers running while using the client.

To create a production bundle, run `npm run build` from `client/`. Vite writes the output to `static/dist/` and generates a manifest. The Django root URL currently renders the template in `templates/index.html`; the Vite bundle is not automatically mounted there by the current configuration.

## API and admin

With Django running, open <http://localhost:8000/api-docs/> for interactive Swagger documentation. The raw OpenAPI schema is available at <http://localhost:8000/api-schema/>. The Django admin is at <http://localhost:8000/admin/>.

The API routes are under `/api/`:

| Route | Purpose |
| --- | --- |
| `POST /api/register` | Create an account |
| `POST /api/login` | Obtain an access and refresh token pair |
| `POST /api/refresh` | Refresh an access token |
| `/api/users` and `/api/users/<id>` | List and manage user records |
| `/api/documents` and `/api/documents/<id>` | List, upload, retrieve, update, and delete documents |

The document endpoints require JWT authentication. Send the access token as `Authorization: Bearer <access-token>`. Uploaded files must use one of the supported extensions and stay within the 5 MB limit.

## Checks

Run backend tests from the repository root. Tests use the configured database, so PostgreSQL must be available and configured first:

```bash
python manage.py test
```

From `client/`, run the frontend checks:

```bash
npm run lint
npm run build
```
